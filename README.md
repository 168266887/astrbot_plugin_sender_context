# 对话者身份注入（astrbot_plugin_sender_context）
> 需搭配人格分流（astrbot_plugin_persona_router）使用

把**当前发言人的身份**（昵称 / 账号 / 群号 / 平台）提供给模型，让「按人分流」的人格设定有判断依据。

## 解决的问题

在人格里写这种条件——

> 面对 QQ 号 168266887 时用 A 人格，面对其他人用 B 人格

——通常不会生效。因为默认情况下模型收到的上下文只有消息文本，**没有发言人的 QQ 号**，
条件分支缺少判断依据，模型只能凭感觉挑一个（往往挑描述更具体的那个）。

本插件会在每次请求里附上一段系统附注：

```
（系统附注，非用户发言）当前对话者信息：昵称=蓝色大肥鱼 | 账号=3196204560 |
场景=群聊(1109034668) | 平台=napcat。判断该用哪副人格/怎么称呼时以此为准……
```

## 为什么不用 system prompt

这是本插件的关键设计取舍。

`system prompt` 位于**供应商 prompt 缓存的前缀**。如果每次请求都往里面拼接会变化的内容
（昵称、账号、群号），缓存命中率会归零，token 成本和首字延迟都会明显上升。

所以身份信息走 `req.extra_user_content_parts`，并用 `mark_as_temp()` 标记为「仅本次请求可见」：

- 不进会话历史（不会被持久化、不会越积越多）
- 不改动 system prompt 前缀（不破坏缓存）
- 每次请求都是最新的发言人信息

## 与「人格分流」插件的关系

| | 表现 |
|---|---|
| 只装本插件 | 模型**知道**对方是谁，能否正确切换取决于模型理解力（不够稳定） |
| 只装 人格分流 | 直接按 QQ 号硬切人格，不需要模型理解 |
| 两个都装 | 最稳：硬切人格 + 保留身份上下文（推荐） |

## 配置

| 项 | 说明 |
|---|---|
| `enabled` | 开关，默认开 |
| `include_group_id` | 是否附带群号，关掉则只标「私聊/群聊」 |
| `debug_mode` | 打开后在日志里打印实际注入内容，便于排查 |
